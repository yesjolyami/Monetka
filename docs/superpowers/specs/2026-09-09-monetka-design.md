# Monetka — design spec

Date: 2026-09-09  
Status: approved  
Product: учебное веб-приложение учёта денег (семейные бюджеты)

README в репозитории не пишем. Этот файл — единственный источник требований до плана реализации.

## 1. Цель

Веб-приложение, в котором несколько людей ведут **общий бюджет**: счета, доходы и расходы, переводы, цели, долги, лимиты, статистика, экспорт и бэкап. Один человек может состоять в нескольких бюджетах и приглашать других в свои.

Это учёт, не банк: нет интеграций с банками, нет инвестиций, нет AI-категоризации.

## 2. Стек

- Последний стабильный Laravel на момент `laravel new`.
- Официальный **Vue starter kit** (Inertia + Vue 3 + Vite), один репозиторий.
- Авторизация из кита: регистрация, вход, сброс пароля. Email-верификация — да, как в ките по умолчанию.
- Pest для тестов.
- Денежные изменения — классы Action (один сценарий = один класс), не толстые контроллеры.
- UI на **русском**.
- Визуальный ориентир: [Copilot Money](https://copilot.money) — характер, не клон бренда и не набор фич Copilot.

Не используем: отдельный Vue SPA + Sanctum CORS, Jetstream Teams, Livewire, двойную бухгалтерскую запись, слияние JSON-бэкапов.

## 3. Арендатор и доступ

### 3.1 Workspace (бюджет)

Пользователь создаёт бюджет: имя + **одна валюта** (ISO-код, например `RUB`, `USD`, `EUR`). Внутри бюджета все суммы в этой валюте, курсов нет.

Создатель становится `owner`. Пользователь может состоять в нескольких бюджетах. Текущий бюджет хранится в `users.current_workspace_id` и должен быть членством этого пользователя. Если поле пустое или членство пропало — берём первый доступный бюджет (по `id`). Переключение в шапке пишет это поле.

Валюту бюджета **нельзя сменить**, если в бюджете уже есть операции. Имя менять можно.

Удалить бюджет может только владелец (с подтверждением). Удаление каскадно снимает данные этого бюджета, не трогая другие.

### 3.2 Роли

| Роль | Может |
| --- | --- |
| `owner` | всё, что участник, плюс: приглашать, исключать, передавать владение, удалять бюджет, импорт с **заменой** текущего бюджета |
| `member` | счета, операции, категории, банки, цели, долги, лимиты, шаблоны, экспорт, просмотр статистики |

Наблюдателя нет. Несколько владельцев нет: владелец **один**. Передача владения: текущий owner назначает другого участника owner и сам становится member.

Владелец не может выйти или исключить себя, пока не передаст владение. Участник может покинуть бюджет.

### 3.3 Приглашения

Только владелец. Email + ссылка с токеном, срок жизни токена 7 дней. Повторный инвайт на тот же email гасит предыдущий токен. Нельзя пригласить уже участника этого бюджета. Принятие логином/регистрацией под этим email (если email другой — отказ с понятной ошибкой). Отклонение гасит токен. После принятия роль `member`.

## 4. Деньги и журнал

### 4.1 Суммы

Хранить `integer` в минимальных единицах валюты (копейки/центы). В UI — десятичное поле, в Action — перевод в integer. `float` в БД и в расчётах остатков запрещён.

Остаток счёта **не колонка**. Для счёта A он равен сумме вкладов журнала:

| type | вклад в остаток A |
| --- | --- |
| `income` | `+amount`, если `account_id = A` |
| `expense` | `−amount`, если `account_id = A` |
| `transfer` | `−amount`, если `account_id = A`; `+amount`, если `counterparty_account_id = A` |
| `adjustment` | `+amount` (знак в поле), если `account_id = A` |
| `goal_contribution` | `−amount`, если `account_id = A` |
| `goal_withdrawal` | `+amount`, если `account_id = A` |
| `debt_repayment` | если `account_id = A`: при `they_owe` `+amount`, при `i_owe` `−amount`; без счёта — 0 |

### 4.2 Типы операций (`transactions.type`)

| type | Смысл |
| --- | --- |
| `income` | доход на один счёт, категория вида income |
| `expense` | расход с одного счёта, категория вида expense |
| `transfer` | списание с `account_id`, зачисление на `counterparty_account_id`, без категории |
| `adjustment` | ручная установка баланса: сумма = новый_остаток − текущий_остаток (может быть отрицательной) |
| `goal_contribution` | пополнение цели со счёта |
| `goal_withdrawal` | возврат с цели на счёт |
| `debt_repayment` | частичный или полный возврат долга; `account_id` необязателен |

Одна запись журнала = одно событие. Перевод не разбивается на две строки.

Поля операции (минимум): `workspace_id`, `type`, `amount` (всегда > 0, **кроме** `adjustment`), `occurred_on`, `account_id` (nullable только у `debt_repayment` без счёта), `counterparty_account_id`, `category_id`, `goal_id`, `debt_id`, `recurrence_id`, `description`, `user_id` (кто записал), timestamps.

Редактирование и удаление операций разрешены участникам. После удаления/правки остатки сходятся сами, потому что вычисляемые.

Запрещено: перевод на тот же счёт; счета/категории/цели/долги из другого бюджета; операция по архивному счёту (правка старых записей архивного счёта — разрешена, новые — нет).

### 4.3 Корректировка баланса

UI «выставить баланс» на карточке счёта. Считаем текущий остаток на сегодня, создаём `adjustment` на разницу. В ленте счёта видна как «корректировка». В статистике расходов/доходов **не** участвует (не топ трат, не линия расходов).

## 5. Справочники бюджета

### 5.1 Банки

`banks`: имя, необязательный цвет. Счёт может быть **без банка** (наличные). Итог по банку на экране счетов = сумма остатков счетов этого банка.

### 5.2 Счета

`accounts`: имя, `type` = `checking` | `savings` (обычный / накопительный — только метка, поведение журнала одинаковое), `bank_id` nullable, `user_id` nullable (`null` = общий счёт бюджета, иначе личный счёт участника). Личный счёт всё равно виден всем участникам бюджета (это семейный учёт, не скрытые кошельки).

При создании: стартовый баланс → сразу `adjustment` (если не ноль).

Архивация — основной способ «убрать». Жёсткое удаление только если **нет** операций. Архивный счёт не принимает новые операции, в общем итоге по желанию фильтр «скрыть архивные» (по умолчанию скрыты из общего итога).

### 5.3 Категории

`categories`: `kind` = `income` | `expense`, имя, эмодзи, цвет. Плоский список, без дерева. При создании бюджета — небольшой дефолтный набор (продукты, транспорт, жильё, кафе, зарплата, …).

Создание из формы операции — то же Action, что и со страницы категорий. Удаление категории **запрещено**, пока на неё ссылаются операции; можно переименовать/сменить эмодзи.

## 6. Цели, долги, лимиты, повторы

### 6.1 Цели

Цель ≠ накопительный счёт. `goals`: имя, `target_amount`, `target_date` nullable, заметка. Прогресс = сумма `goal_contribution.amount` − сумма `goal_withdrawal.amount`. Пополнение и снятие всегда через счёт. Цель без привязки «жить на конкретном накопительном счёте».

### 6.2 Долги

`debts`: `direction` = `they_owe` | `i_owe`, имя контрагента (строка, не обязательно пользователь системы), `original_amount`, заметка. Остаток = original − сумма `debt_repayment` по этому долгу (не ниже нуля: очередной возврат нельзя сделать больше остатка). Возврат без счёта только уменьшает остаток долга. Возврат со счётом ещё и двигает баланс: «мне вернули» (`they_owe`) — деньги на счёт; «я вернул» (`i_owe`) — деньги со счёта. Долг не является счётом.

### 6.3 Лимиты

`category_limits`: `category_id` (только expense), `amount` на **календарный месяц**. Факт месяца = сумма `expense` этой категории. При факте > лимита — предупреждение в UI и на статистике. Сохранить расход сверх лимита **можно**.

Перенос неиспользованного лимита на следующий месяц **нет** (не копируем rollover Copilot).

### 6.4 Повторяющиеся шаблоны

`recurrences`: шаблон только для `income` | `expense` | `transfer` + `frequency` = `weekly` | `monthly` | `yearly` + `next_occurred_on` + `is_active`. Сами не проводятся (нет cron в v1). Кнопка «провести ближайшее» создаёт обычную `transaction` с `recurrence_id` и сдвигает `next_occurred_on` на один шаг частоты. Операцию после этого можно править как любую другую; шаблон от этого не меняется, пока его не отредактируют. Остановка: `is_active = false`.

## 7. Интерфейс

### 7.1 Визуальный язык

Ориентир — Copilot Money: тёмный navy-холст и равноправная светлая тема; мало рамок; сумма — главный акцент экрана; тонкая линия трат; категории — чипы с эмодзи; семантические цвета данных.

Токены (ориентиры, не пиксель-перфект копия):

- Dark: canvas `#000814`, surface `#001533`, text `rgba(255,255,255,0.9)`, muted `#7F8BA4`
- Light: canvas `#F9FAFC`, surface `#FFFFFF`
- Income `#00CC4B`, expense `#FF4433`, warning `#FECE4C`, accent `#1C6CFF`

Шрифты с открытой лицензией (не Jokker/Matter): display — **Instrument Serif**; UI — **Geist**. Не копировать логотип, имя и маркетинговые иллюстрации Copilot. Не имитировать iOS Liquid Glass.

Тема: `light` | `dark` | `system` на пользователе. Переключатель в шапке. `system` — по `prefers-color-scheme`. Значение по умолчанию `system`.

### 7.2 Каркас

Левый сайдбар: Обзор, Операции, Счета, Цели, Долги, Лимиты, Статистика, Настройки бюджета. Шапка: переключатель бюджета, тема, профиль. Пункты «участники / удалить бюджет» только у owner.

Пустой бюджет: короткий онбординг, предложить создать первый счёт.

### 7.3 Экраны

**Обзор.** Крупный итог видимых счетов, линия расходов текущего месяца, состояние лимитов, ближайшие шаблоны, цели с прогрессом, краткие долги. Не больше этого набора.

**Операции.** Лента за выбранный месяц: описание, чип категории, счёт, сумма. Фильтры: месяц, счёт, категория, тип. Формы доход / расход / перевод; в форме — быстрая категория. Правка, удаление с подтверждением.

**Счета.** Группы по банкам + блок без банка; внутри — общие и личные. Итог по банку. Карточка счёта: остаток, фильтр месяцев, лента, выставить баланс, архив.

**Цели / долги / лимиты.** Как в §6, прогресс-бары, предупреждение лимита жёлтым.

**Статистика (выбранный месяц).**

- Сравнение расходов и доходов с предыдущим месяцем
- Динамика расходов за 6 месяцев
- Топ категорий расходов
- Прогноз расходов текущего месяца: `уже потрачено в этом месяце + среднесуточный расход за предыдущие 6 полных месяцев × оставшиеся дни`. Если полных месяцев меньше шести — среднее по тем, что есть; если истории нет — среднесуточный расход текущего месяца × оставшиеся дни. Для прошлых месяцев прогноз не показываем. Без ML.

**Настройки.** Имя бюджета; валюта (readonly, если есть операции); участники и инвайты (owner); экспорт/импорт.

## 8. Экспорт и импорт

### 8.1 CSV

Таблица операций текущего бюджета (фильтр месяца — тот, что на экране, либо «все» явно). Колонки, понятные Excel/Numbers: дата, тип, сумма (десятичная), валюта, счёт, счёт-получатель, категория, описание. Кодировка UTF-8 с BOM.

### 8.2 PNG

Снимок блока статистики (итог, топ, сравнение, линия) клиентским рендером в PNG.

### 8.3 JSON-бэкап

Версионированный снимок **одного** бюджета: мета (имя, валюта, `schema_version: 1`), банки, счета, категории, операции, цели, долги, лимиты, шаблоны. Без пользователей, паролей, инвайтов, других бюджетов. Владельцы личных счетов в файле — email. При импорте: если такой email уже участник целевого бюджета — привязать; иначе счёт становится общим (`user_id` null). Авторство операций в новом бюджете — пользователь, который импортирует.

### 8.4 Импорт

1. **Новый бюджет** — доступно любому залогиненному. Создаёт workspace из файла, импортирующий пользователь = owner.  
2. **Заменить этот бюджет** — только owner, чекбокс подтверждения, что текущие данные бюджета будут уничтожены. Другие бюджеты не трогать.

Слияния нет. Неизвестная `schema_version` (новее 1) — отказ с ошибкой. v1 — единственная версия на старте.

## 9. Ошибки и целостность

Все Action, меняющие деньги или состав бюджета, в `DB::transaction`. Валидация — Form Request, в контроллер только `validated()`. Авторизация — policies + `workspace_id` из текущего бюджета, никогда из произвольного input без проверки членства.

Сообщения об ошибках на русском, без стека в UI.

## 10. Тесты (Pest)

Минимум:

- Остаток счёта после income, expense, transfer, adjustment, удаления операции
- Перевод на тот же счёт / в чужой бюджет — 422 / 403
- Лимит: расход проходит, флаг exceeded = true
- Инвайт: принять, повторный токен, запрет пригласить участника
- Policy: member не приглашает и не заменяет бэкапом
- Импорт создаёт новый бюджет с тем же числом операций
- Корректировка не попадает в сумму расходов статистики

Feature-тесты Inertia на: логин, создание бюджета, создание счёта, расход, перевод. Не тестировать пиксели темы.

## 11. Вне скоупа v1

Банковские API, мультивалюта внутри бюджета, роли с матрицей прав, наблюдатель, несколько владельцев, автопроведение повторов по cron, вложения/чеки, скрытые личные счета от других участников, merge-импорт, мобильные приложения, README.

## 12. Критерий готовности продукта

Залогиненный пользователь создаёт бюджет, приглашает второго, оба ведут общие и личные счета, ставят цель и долг, видят лимит и статистику месяца, переключают тему, выгружают CSV/PNG/JSON и восстанавливают JSON как новый бюджет. Pest-сюита зелёная.
